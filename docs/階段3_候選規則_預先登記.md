**登記日期**：2026-09-10
**探索期依據**：`docs/飆股解剖_v2.md`（月營收覆蓋 1,897/1,980 = 95.8%）
**狀態**：🔒 凍結。本文件一旦 commit，規則定義與判定門檻不得再修改。
**用途**：在動用保留期（holdout）資料之前，先把「要驗證什麼」「怎樣算成功」寫死，避免事後調參自我欺騙。

## 0. 為什麼需要這份文件

探索期（2021-09-01 ~ 2024-12-31）我已經看過非常多次資料，跑過數十種特徵切法。
在這種情況下，**任何在探索期表現好的規則都可能只是被我挑出來的雜訊**。

保留期（2025-01-01 ~ 2026-05-31）從專案開始到現在**一次都沒有被讀取過**。
它只能用一次。用完之後，如果我再回頭改規則、再用一次保留期，保留期就失效了，
整個研究就退化成「在全部資料上調參」，結論不可信。

所以：**先寫死規則 → commit → 才准跑 `lift.py --holdout`**。

## 1. 候選規則定義（Rule R1）

### 1.1 母體（universe）

與探索期完全相同的過濾條件，不得放寬：

| 條件 | 值 | 來源 |
|---|---|---|
| 最低成交金額 | 20 日均額 ≥ 5,000,000 元 | `research/features.py:MIN_TURNOVER` |
| 資料完整性 | 該日需有完整 OHLCV 且前 60 日無缺漏 | `research/features.py` |
| 市場 | 上市 + 上櫃 | 資料庫既有範圍 |

### 1.2 訊號條件

同一交易日，**同時**滿足下列兩條：

1. **股價近 52 週高點**：`dist_52w_high` 在**當日橫斷面前 10%**（decile 10）
2. **月營收年增率**：`rev_yoy` 在**當日橫斷面前 10%**（decile 10）
   - 採 point-in-time 對齊（`research/features_revenue.py` 的 `merge_asof`），
     只使用**該日已公告**的月營收，不得使用未來公告值。

> 兩個條件都是**當日橫斷面分位**，不是絕對門檻。
> 這是刻意的：絕對門檻會隨大盤水位漂移，橫斷面分位不會。

### 1.3 事件化（episode）

連續觸發視為同一事件，**只取事件的第一天**：

- 同一 ticker 的觸發日，若間隔 ≤ 5 個交易日，歸為同一 episode
- 每個 episode 只計入第一個觸發日
- 依據：`research/episodes.py:GAP = 5`

> 理由：不做事件化的話，一檔股票連漲 20 天會貢獻 20 筆「獨立」樣本，
> 統計檢定的自由度是假的，信賴區間會過窄。

### 1.4 標籤（label）

- **主標籤**：`flyer_100` — 未來 60 個交易日內，最高價相對訊號日收盤價漲幅 ≥ 100%
- **次標籤**：`flyer_120` — 未來 120 個交易日內漲幅 ≥ 100%
- **報酬指標**：`excess_60` — 60 日報酬減去**同期、同母體（過濾後）**的橫斷面平均報酬

## 2. 判定門檻（Success Criteria）

保留期跑完後，依下表判定。**門檻在此凍結，事後不得調整。**

| # | 指標 | 通過門檻 | 說明 |
|---|---|---|---|
| C1 | episode 樣本數 | **n ≥ 200** | 低於此數，統計檢定無意義，判定為「資料不足」而非「失敗」 |
| C2 | `flyer_100` lift 的 Wilson 95% CI 下界 | **> 1.0** | 命中率確實高於母體基準率，且下界不觸及 1 |
| C3 | `excess_60` 的 95% CI 下界 | **> 0** | 超額報酬為正，且下界不觸及 0 |
| C4 | `excess_60` 點估計 | **≥ +2.0%** | 探索期為 **+5.48%**；容許縮水，但不得縮到沒有實務意義 |
| C5 | 勝率 | **≥ 45%** | 探索期 **49.7%**。低於 45% 代表獲利高度集中在少數極端值，實務上難以持有 |

**探索期對照值（保留期要打敗的不是這些數字，而是上面的門檻）**：
n = 1,510 事件 ｜ 命中率 4.97% ｜ lift 3.65 ｜ 超額 +5.48% [+3.80, +7.15] ｜ 勝率 49.7% ｜ 每年 453 次

### 判定規則

- **全數通過（C1–C5）** → 規則 R1 通過外部驗證，進入階段 4（排序規則與部位管理）
- **C1 未達** → 判定「保留期樣本不足」，不算失敗也不算成功；不得因此放寬條件重跑
- **C2 或 C3 失敗** → 規則 R1 **否決**。探索期結果判定為過度配適
- **C2、C3 通過但 C4 或 C5 未達** → 判定「方向正確、強度不足」，
  記錄為部分成立，但**不得**直接用於實盤；需重新設計並取得新的保留期

## 4. 執行程序（一次性）

```
1. 本文件 commit 完成，且 git working tree 乾淨
2. python scripts/check_freeze.py        # 確認參數未漂移
3. python research/lift.py --holdout     # 需手動輸入 YES 確認
4. 結果原樣寫入 docs/階段3_保留期結果.md，含失敗項目
5. 依第 2 節判定，不得事後調整門檻
```

**執行次數上限：1 次。**
若因程式錯誤導致執行失敗（例外、資料讀取錯誤），修正後可重跑，
但**必須在 `docs/階段3_保留期結果.md` 中記錄每一次執行與失敗原因**。
「結果不好看」不構成重跑理由。

## 6. 已知限制（誠實記載）

1. **月營收覆蓋率**：本規則所用的 `rev_yoy` 來自 FinMind 免費層逐檔補抓，
   完成度以 `research/data/` 實際覆蓋為準。覆蓋不足的個股在該日不會觸發訊號，
   這是**系統性缺漏**而非隨機缺漏 —— 補抓順序雖已用固定種子亂數化以避免產業偏誤，
   但仍可能低估真實訊號數。
2. **無法回推下市股票**：資料庫只含目前仍在市的個股，存在生存者偏誤，
   會使歷史報酬系統性偏高。此偏誤在探索期與保留期同時存在，
   故不影響「探索 vs 保留」的比較，但會使絕對報酬數字偏樂觀。
3. **未計交易成本**：`excess_60` 未扣手續費、證交稅、滑價。
   台股單趟成本約 0.6%（來回含稅），實務報酬需再扣約 0.6–1.0%。
4. **翻倍標籤本身獎勵波動**：探索期已證實 ATR decile D1→D10 命中率 20 倍、
   但超額報酬持平。R1 之所以可信，是因為它的超額報酬呈單調且勝率提升，
   不是純粹靠波動放大。此點在保留期需再次確認（見 C5）。
