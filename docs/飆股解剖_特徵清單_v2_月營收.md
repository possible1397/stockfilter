## 2. Point-in-time 規則（本階段最容易犯的致命錯誤）

M 月的營收在 **M+1 月 10 日前**公布。因此:

```
可用日 = M+1 月的 11 日（保守，避開公布當天的不確定性）
```

任何交易日 t 只能看到「可用日 <= t」的營收。實作上用 as-of merge：
把每筆營收貼上可用日，再以 backward as-of 對齊到日線。

**若把 M 月營收用在 M 月的交易日上，就是前視偏誤，整個階段 2 作廢。**
`features_revenue.py` 會在輸出前 assert 每一列的營收可用日都 <= 該交易日。

## 3. 特徵清單（6 個，清單凍結）

全部基於「截至該交易日已公布」的營收序列。

| # | 名稱 | 定義 |
|---|---|---|
| 21 | `rev_yoy` | 最新已公布月營收的年增率 |
| 22 | `rev_yoy_3m` | 最近 3 個月營收合計的年增率（平滑單月雜訊） |
| 23 | `rev_yoy_accel` | `rev_yoy` 減去上一個月的年增率（**加速度**） |
| 24 | `rev_mom` | 最新月營收的月增率 |
| 25 | `rev_streak` | 年增率連續為正的月數（上限 24） |
| 26 | `rev_high_12m` | 最新月營收是否為近 12 個月最高（0/1） |

**為什麼是這 6 個**:台股飆股的常見引信是營收拐點，而拐點的訊號是
「加速度」與「創新高」，不只是「成長率高」。所以 23 與 26 是這組的重點，
21/22/24 是基準，25 衡量趨勢的持續性。

## 4. 評估方式（與 v1 完全相同，不另立標準）

- 標籤不變:主標籤 `flyer_100`（60 個交易日內最大漲幅 ≥ 100%），
  並排報告 `flyer_50` 與 `flyer_120`
- 分位不變:同日橫斷面十分位
- 判準不變:**命中率與期望報酬的信賴區間都要過**才算候選
- 期間不變:探索期 2021-09-01 ~ 2024-12-31。**保留期仍然不動**
- 超額報酬基準不變:可交易母體內同日等權平均

## 5. 預期與預先寫下的判讀規則

先寫下預期，免得事後把任何結果都說成「早就知道」:

- **若營收特徵的超額報酬明顯優於 v1 的價量特徵**（例如 D10 超過 +3%），
  代表基本面維度確實補上了缺口，階段 3 的候選組合應納入營收條件
- **若與價量特徵相當或更弱**，代表月營收在 60 日尺度上已被價格反映，
  結論是「免費資料的邊界大概到此為止」，階段 3 只用價量候選
- **若完全沒有訊號**，這是強資訊:它會讓「付費買籌碼資料」的預期報酬也一併下修

三種結果都會如實寫進 `docs/飆股解剖_v2.md`。

## 6. 已知限制

1. **營收公布日是估計值**（統一用次月 11 日），實際各公司不同。
   保守方向:寧可晚一天，不可早一天
2. **新上市公司**的營收序列短，年增率不可得，該列為 NaN
3. FinMind 免費層有配額，抓取可能中斷。腳本可續跑，但資料快照日期會不一致
4. 月營收只到「合併營收」層級，沒有毛利、產品組合等更細的資訊
